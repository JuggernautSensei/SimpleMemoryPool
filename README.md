# SimpleMemoryPool

메모리 풀의 동작 원리를 설명하는 포스팅과 함께 작성한 **C++20 헤더 전용 메모리 풀 구현**입니다.

비교적 단순한 고정 크기 블록 풀을 통해 메모리의 할당·반납·재사용 과정을 살펴봅니다. 저수준 메모리 관리에 대한 이해를 점검하고, 메모리 정렬을 직접 적용해 보는 목적으로 구현했습니다.

이 문서는 포스팅의 요약입니다. 구현 과정과 코드에 대한 자세한 설명은 아래 글에서 확인할 수 있습니다.

📖 [메모리 풀과 간단한 구현](https://purple-jingle-7d5.notion.site/3c5c3fb6c02f8041b2d5e177d24cab3d?source=copy_link)

## 핵심 원리

메모리 풀은 큰 메모리 영역을 확보한 뒤, 그 안에서 필요한 공간을 나누어 사용하는 방식입니다. 개별 요청마다 범용 할당자를 호출하는 횟수를 줄이고, 사용이 끝난 공간을 재사용할 수 있습니다.

이 저장소의 중심인 `FixedBlockPool`은 메모리를 **같은 크기의 블록**으로 나누어 관리합니다.

```text
풀 하나
[헤더 + 정렬 패딩][블록 0][블록 1][블록 2] … [블록 N-1]
```

### 할당

반납된 블록이 있으면 먼저 재사용합니다. 반납된 블록이 없으면 현재 풀에서 다음 블록을 반환하고, 포인터를 블록 크기만큼 전진시킵니다.

풀의 메모리는 첫 할당 요청 시 확보하며, 현재 풀을 모두 사용하면 새로운 풀을 추가합니다.

### 반납과 재사용

`Free()`는 블록을 범용 할당자에 돌려주지 않습니다. 반납된 블록 안에 다음 빈 블록을 가리키는 포인터를 기록해 **free list**로 연결합니다.

```text
반납: 블록을 free list 앞에 연결합니다.
할당: free list의 첫 블록을 꺼내 재사용합니다.
```

사용이 끝난 블록 자체를 연결리스트의 노드로 활용하므로, 노드를 위한 별도 메모리 할당이 필요하지 않습니다. 확보한 풀 전체는 `Reset()` 또는 소멸 시 해제합니다.

### 메모리 정렬

각 블록의 시작 주소가 요청한 정렬 조건을 만족하도록 블록 크기를 올림합니다. 풀 앞부분의 헤더에도 패딩을 적용해 첫 블록의 정렬을 유지합니다.

## 구현 구성

| 헤더 | 역할 |
| --- | --- |
| `Base.h` | 주소·크기 정렬과 플랫폼별 정렬 메모리 할당·해제를 제공합니다. |
| `FixedBlockPool.h` | 고정 크기 블록의 할당, 반납, 재사용을 관리합니다. |
| `ObjectPool.h` | `FixedBlockPool`에 타입별 객체 생성·소멸을 연결합니다. |
| `MemoryArena.h` | 메모리를 순차적으로 할당하고 한 번에 해제합니다. |

## 사용 방법

외부 라이브러리나 별도 링크 과정 없이 저장소 루트를 헤더 탐색 경로에 추가하면 됩니다.

```cpp
#include "FixedBlockPool.h"

int main()
{
    // 블록당 32바이트, 풀당 127개입니다.
    jug::FixedBlockPool pool(32, 127);

    void* block = pool.Alloc();
    // 반환된 공간을 사용합니다.

    pool.Free(block);
}
```

C++20 이상과 MSVC 또는 `posix_memalign()`을 지원하는 POSIX 환경의 C++ 컴파일러가 필요합니다. 위 예제를 `main.cpp`로 저장했다면 Linux/GCC에서 다음과 같이 실행할 수 있습니다.

```sh
g++ -std=c++20 -Wall -Wextra -Wpedantic -I . main.cpp -o example
./example
```

## 성능 비교

`FixedBlockPool`과 `malloc/free`를 비교한 기존 측정 결과입니다.

- 컴파일 환경: MSVC, x64 Release
- 블록 크기: 32바이트
- 풀당 블록 수: 127개
- 풀 하나의 크기: 헤더·패딩을 포함해 4,080바이트

| 시나리오 | malloc/free | FixedBlockPool | 배율 |
| --- | ---: | ---: | ---: |
| 200만 회 할당 후 일괄 해제 | 144.851 ms | 18.704 ms | 7.74배 |
| 할당 직후 해제 500만 회 반복 | 157.437 ms | 2.950 ms | 53.38배 |
| 랜덤 할당·해제 혼합 | 145.569 ms | 47.004 ms | 3.10배 |
| 힙 파편화 + 프레임 단위 생성·소멸 | 136.961 ms | 6.558 ms | 20.88배 |

성능 차이는 실행 환경과 할당 패턴에 따라 달라집니다. 측정 시나리오의 자세한 설명은 포스팅에 있으며, 벤치마크 소스는 현재 저장소에 포함되어 있지 않습니다.

## 사용 시 주의사항

동작 원리를 살펴보기 위한 간단한 구현으로, 호출자가 다음 조건을 지켜야 합니다.

- **블록 크기와 정렬:** free list가 블록 안에 포인터를 기록합니다. 정렬 후 블록 크기는 `sizeof(void*)` 이상, 블록 정렬은 `alignof(void*)` 이상이어야 합니다. `ObjectPool<T>`의 타입도 이 조건을 만족해야 합니다.
- **포인터 반납:** 해당 풀에서 받은 포인터만 한 번 반납해야 합니다. 잘못된 포인터와 이중 해제를 검사하지 않습니다.
- **객체 수명:** `ObjectPool`에 남아 있는 객체의 소멸자를 자동으로 호출하지 않습니다. 생성한 객체는 풀 소멸 전에 `Delete()`해야 합니다.
- **아레나 요청 크기:** 요청한 공간과 내부 헤더·정렬 패딩이 풀 하나 안에 들어가야 합니다.
- **동시 접근:** 내부 동기화가 없으므로 여러 스레드에서 같은 풀을 사용하려면 외부 동기화가 필요합니다.
- **할당 실패:** 메모리 할당 실패에 대한 복구 처리를 제공하지 않습니다.

`Reset()` 또는 풀 소멸 이후에는 기존에 반환받은 포인터를 사용할 수 없습니다.
